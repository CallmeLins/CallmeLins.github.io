常见问题

部署、认证、迁移、调度、插件相关的高频疑问。若这里没有答案，欢迎到 GitHub Issues 提问。

部署与会话

HTTPS 部署后登录会话不生效 / 一直被登出？

生产环境必须把 COOKIE_SECURE 设为 true，否则安全 Cookie 不会被浏览器接受。

邮件相关功能（重置密码、邮箱验证、Email 渠道）用不了？

需要先配置 QDRUST_SMTP_* 系列环境变量，并确认 QDRUST_BASE_URL 指向对外可访问的地址（邮件里的链接以此拼接）。

若启用了 REQUIRE_EMAIL_VERIFICATION，新用户必须验证邮箱才能登录——SMTP 没配好时会表现为「注册成功但登不进去」。

多实例 / 横向扩展怎么弄？

单实例基于 SQLite 事务 + 租约保证不重复执行；多实例共享数据库时同样由租约机制保证。推荐 docker compose up --scale qdrust=N 加反向代理。Redis 仅用于会话缓存加速，非必需。

需要注意的是，无头浏览器会话是进程内状态，不跨实例共享。

认证与第三方登录

QDRUST_AUTH_MODE=oidc 但页面没有直接跳转 IdP / 只看到登录面板？

纯 OIDC 模式下未登录访问应自动跳转到 IdP 发起 SSO。只有两种情况会停留并显示 SSO 兜底面板：

  • 当前已带 ?login_error=（上次回调失败，给你一个可重试的入口，避免跳转死循环）；
  • 页面已登录。

若你始终停留在面板，多半是回调带上了遗留的 login_error 参数——清掉 URL 参数刷新即可。

另见使用指南 · 纯 OIDC 模式的登录体验。

OIDC 登录了，但点登出又回到登录页，IdP 侧会话还在？

默认只清除 qdrust 本地会话。要让提供方会话一起结束，配置 QDRUST_OIDC_LOGOUT_URL 指向 IdP 的 end-session 端点（authentik：.../protocol/openid-connect/logout； Keycloak：.../realms/<realm>/protocol/openid-connect/logout）。

可选配 QDRUST_OIDC_POST_LOGOUT_REDIRECT_URI 让 IdP 登出后跳回应用——仅当该地址已在 IdP 的 OIDC 客户端登记过才配，否则多数 IdP 会拒绝未登记的回跳参数。

迁移与升级

数据库升级后还能回退到旧版本吗？

迁移是前向 only 的。仅回退镜像而不恢复数据库不被支持；回退请同时用备份恢复数据库，再启动旧镜像 digest。

能直接导入旧 QD 的数据吗？

qdrust 不导入旧 QD 数据库、不复用旧登录 Cookie、不承诺兼容旧 URL / 旧 API / 任意 Python 动态表达式。旧 QD 的 HAR 模板是唯一的核心兼容契约——在 WebUI 里导入 *.har.json 即可，导入时会校验并保留原始 HAR JSON。

插件 / api://util 工具不全？

api://util/* 已对齐 QD 的核心工具（时间 / 编码 / 哈希 / 正则 / JSON / RSA / GB2312 / 字符串替换 / OCR / TOTP）。 TOTP（RFC 6238）在本地算码，2FA 密钥不出网，表达式侧也可以写 {{ totp(secret) }}。

旧 QD 的 toolbox 与 notepad 属于 Web 工具箱页面，不在模板 API 范围内，未移植。

升级后任务忽然报「模板不存在」，或想引用同事的模板报 404？

v0.1.17 起模板绑定按任务所有者隔离：校验任务时，template_id 先按调用者自己的归属查找，之后才考虑请求里带的 URL。 此前 URL 会短路这次查找——只要附上任意 URL，就能引用乃至执行别人的模板。这是安全修复，同时是破坏性的。

指向他人模板的 template_id 现在一律按「不存在」返回（错误信息也不会确认它是否存在）。如果你确实需要共享模板，用「公共模板」发布 / 复制机制，而不是直接引用对方的模板 id。

调度与运行

新建任务时为什么不用填请求方法 / URL / 请求头 / 请求体？

因为任务的请求完全由模板决定——调度器执行时直接重放模板（多页模板常混合 GET/POST）， 任务自带的这几个字段从来不会被使用。所以新建任务必须先选模板，请求方法 / URL 只在任务列表里作为模板首条请求的镜像展示。

唯一例外是早于该改动的存量任务（没有绑定模板、自带一条请求），编辑它们时模板下拉会保留「（无模板）」选项， 其原有请求也不会被改动。

订阅了模板库，为什么模板没有自动出现在「我的模板」里？

这是刻意设计：订阅只登记一个来源目录，不会自动把上游模板拉进本地——官方库有几百个模板，全量导入会把你自建的模板淹掉。 到模板页的「公共模板」列表里逐条「导入」（点开的是预览，保存才入库），或用「批量选择」直接批量导入。 已导入的模板在上游版本变新时会标「有更新」，点「更新」先预览、保存后原地更新，不会生成重名副本。

调度好像没按我设的时间跑？

SCHEDULER_INTERVAL_SECONDS（默认 15 秒）是调度器轮询间隔，任务触发精度受其影响。如需更精确请相应调小——代价是更频繁的数据库轮询。

运行记录越来越多，能自动清理吗？

设置 LOG_RETENTION_DAYS（默认 0 永久保留），系统每小时清理超出天数的已完成运行。也可以在任务详情页手动清空某个任务的运行历史。

任务没拿到响应（超时 / DNS 失败），状态为什么是「失败」？

「失败」的判据是上一轮运行是否留下错误（last_error 非空），而不是只看 HTTP 状态码。 连接层就没成的情况（TLS 握手失败、DNS 解析不了、超时）根本拿不到响应，last_status 是空的——这类运行此前会被显示成「正常」，现在按「失败」计入。 概览卡片的「最近失败」同理。从未运行过的任务是「正常」（两个字段都空）。

任务列表的「状态」列还有第三档「禁用」（disabled），它优先于「失败」与「正常」。

为什么需要「随机延迟」？

它让同一任务的多次执行在时间上打散，避免被目标站点识别为固定节奏。对于签到类任务，这是一个实用而非装饰性的功能。可视化调度器里直接开启即可。

网络、安全与模板行为

CLI 报网络被拒绝（私网 / localhost / 证书）？

CLI 是刻意的更严格策略——默认拒绝私网、localhost 和无效 TLS 证书，不像旧 QD 那样宽松。

服务端现在也有闸门：默认只请求公网地址，覆盖模板运行、不绑模板的任务、通知渠道与测试、订阅抓取、api://util/dddd 转发共五条路径。 指向内网 / 回环或使用自签证书时，需要在管理页开启对应的高风险开关——见下一个问题。

任务 / 渠道 / 订阅突然报 private or special-use network target is blocked？

这是 SSRF 防护在起作用（v0.1.16 起统一覆盖全部出站请求，不再只是模板）。升级后原先能用的内网通知渠道（自建 ntfy）、 内网 GitLab 订阅源、自建 DdddOCR 服务都会失败，需要到管理页「站点设置」开启 允许出站请求访问内网地址。

另外两点容易忽略：出站请求一律不再跟随重定向（.../raw/... 这类会 302 到 raw.githubusercontent.com 的地址要直接写最终地址）； 代理地址（模板里的 _proxy）本身也要过同一道闸门，指向内网需同样开启开关。

自签 / 过期证书报的是证书错误而不是 SSRF 错误，那需要另一个开关：接受无效证书。

模板里能写 Python 吗？

不能。qdrust 模板是声明式 JSON，不执行 Python 或任意代码。动态能力来自 Jinja2 表达式（minijinja）与 api://util/* 内置工具。

同时有硬性上限：最多 1000 个静态步骤、16 层嵌套、单次 delay 最长 5 分钟，运行期另外限制请求数、循环次数、响应体大小与总时长。

模板报 invalid QD regular expression？

先看报错里点名了什么构造，两类含义相反。以下写法是旧 QD 的 Python re 认、这里的引擎不认（或会读成别的意思）的， 需要改写该 re：{m,n} 里 m > n、\N{...}（Python 命名字符）、(?a)（ASCII 内联 flag）。

而 (?<name>…)、(*FAIL) 这类回溯动词、(?-i) 这种「组外关 flag」是反方向： Python 本来就不认，只有这里的引擎会接受——报错是在提醒你这个 re 在 QD 上本来也跑不起来，一并改掉。

已经支持、不必再绕开的：lookaround（(?= (?! (?<= (?<!）、反向引用（\1）、 八进制转义（\012 / \123 / [\1]）与条件组 (?(id)yes|no)。若弹的是「needed more backtracking」， 说明该 re 在回溯引擎里代价过高，改写它就能过。完整规则见模板与表达式 · 正则。

浏览器插件

站点要 JS 生成签名 / 过验证码，纯 HAR 跑不了怎么办？

用 api://browser/* 无头浏览器插件。配置 QDRUST_BROWSER_URL 后启用，模板里插入 api://browser/eval（执行 JS 取 token / 签名）、api://browser/content（抓渲染后 HTML）或 api://browser/screenshot（截图），再用 extract_variables 把结果提成变量回填。详见 浏览器插件。

浏览器插件能自动跑多步页面交互（点按钮、填表单）吗？

可以。用 start 开一个会话，对同一 session 跨步骤执行 type（输入）/ click（点击）/ content（取渲染后状态），把会话 id 提出来后用 {{var}} 复用于后续步骤；流程结束用 end 关会话。

会话在 server 内存中跨调用存活（空闲 30 分钟 / 最长 24 小时回收），所以中途可以停下等人——比如让人工过完验证码再继续。会话里的 # 等选择器要 URL 编码（#id → %23id）。

浏览器步骤失败会中断整个任务吗？

不会。未配置 QDRUST_BROWSER_URL、连接失败、找不到元素或会话、参数缺失等都会返回 502 信封，可用 success_asserts / failed_asserts 感知——不会静默降级，也不会中断整个任务。

服务重启后浏览器会话还在吗？

不在。会话存于 server 内存，进程重启即全部清空，向导需要重新 start。这是单进程模型的取舍：换来的是 DOM 状态可以在多次独立调用间存活。

其他

想让首次访问的人默认看到英文界面？

设 QDRUST_DEFAULT_LOCALE=en-US（也接受裸 en；默认 zh-CN）。它只是默认值： 页头语言切换器选过的语言存在该浏览器里，已存偏好永远优先，所以它不会把老用户的语言改回去。WebUI 在挂载前经 GET /api/v1/meta 读取它。
