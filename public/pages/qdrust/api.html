API 接口

qdrust 服务端的完整 REST 契约：79 个端点，覆盖认证、模板、任务调度、运行记录、订阅同步、通知、插件与站点管理。

v0.1.8 REST · JSON OpenAPI 3.1 Cookie + CSRF
机器可读版本

服务内嵌了同一份契约的 OpenAPI 3.1 文档，运行时可直接取用：GET /api/v1/openapi.json。 把它丢进 Swagger UI 或导入 Postman 即可获得可交互的接口调试台。本页内容由该文档与 crates/qdrust-server/src/api.rs 共同核对生成。

概览

所有业务接口挂在 /api/v1 下，请求与响应一律 application/json。 非 /api 前缀的路径由前端静态资源兜底，因此拼错接口会先命中 SPA 的 index.html——只有带 /api 前缀却不存在时，才返回统一的 404 信封。

认证与会话

认证走 Cookie，不使用 Bearer Token。登录成功后服务端下发两个 Cookie：

Cookie属性作用
qd_sessionHttpOnly · SameSite=Strict会话令牌，前端脚本读不到，服务端只存其 SHA-256
qd_csrfSameSite=StrictCSRF 令牌，前端可读，需回写到请求头

写操作需带 CSRF 头：POST / PUT / PATCH / DELETE 必须携带 x-csrf-token，其值与 qd_csrf Cookie 完全一致。服务端会做两件事——比对 Cookie 与头是否相同，再校验其哈希是否与会话中记录的相符，任一不符即 403 csrf_validation_failed。比对用常量时间，不泄漏时序信息。 

# 浏览器里取出 CSRF Cookie 并回写
curl -X POST http://localhost:5000/api/v1/tasks \
  -b "qd_session=$SESSION; qd_csrf=$CSRF" \
  -H "x-csrf-token: $CSRF" \
  -H "Content-Type: application/json" \
  -d '{"name":"签到","cron":"0 9 * * *","url":"https://example.com"}'

错误信封

所有非 2xx 响应结构一致。code 是稳定的错误键，前端据此做本地化，message 只是英文兜底文案； field_errors 给出逐字段的校验失败原因；request_id 用于对照服务端日志。内部异常细节只写日志，不出现在响应里。 

{
  "code": "validation_error",
  "message": "cron expression is invalid",
  "field_errors": { "cron": ["must be a valid cron expression"] },
  "request_id": "7f3c1e9a2b8d4f6e"
}
Code状态含义
api_endpoint_not_found404/api 下无此路由
task_not_found404任务不存在
run_not_found404运行不存在，或不属于当前用户
template_not_found404模板不存在
validation_error422请求体或领域校验失败，看 field_errors
authentication_required401会话缺失、过期、被吊销或账号已禁用
invalid_credentials401用户名或密码不对
csrf_validation_failed403CSRF 三元组（Cookie / 头 / 会话哈希）校验失败
admin_required403需要管理员角色
bootstrap_already_completed409首个管理员已存在，不可重复初始化
login_rate_limited429该用户名登录失败过多，暂时限流
internal_error500未预期的内部错误

分页与限流

列表接口用游标分页而非 offset：limit 默认 50、上限 200，响应回 next_cursor，为 null 即末页。 这样在频繁写入的场景下翻页不会漏项或重复。

登录接口单独限流：同一用户名在窗口内失败超过阈值即返回 429 login_rate_limited，成功一次即清零。 阈值与窗口由启动参数配置，目的是挡住针对固定用户名的暴力枚举。

WebSocket 实时接口

两个实时端点都用普通 HTTP 握手升级，因此仍走同一套 Cookie 鉴权——浏览器可直接连，非浏览器客户端带上 qd_session 即可。 服务端以文本帧推送 JSON，客户端无需发送任何消息。

端点推送内容
/api/v1/runs/{id}/steps/live该次运行的步骤明细与状态变更
/api/v1/subscriptions/{id}/sync/live模板订阅的同步进度

帧体即 RunEvent：type 为 status（运行状态变更）、step（单个步骤完成）或 snapshot（连接建立时的全量快照，用于补齐连上之前已产出的步骤）。 先收 snapshot 再收增量，客户端就能在任意时刻接入而不丢数据。 

{"type":"snapshot","run_id":42,"status":"running"}
{"type":"step","run_id":42,"step":{"index":0,"url":"https://example.com","status":200}}
{"type":"status","run_id":42,"status":"success"}

一次完整调用

从初始化管理员到拿到运行结果，串起最小可用链路： 

# 1) 初始化首个管理员（只能成功一次）
curl -c jar.txt -X POST http://localhost:5000/api/v1/auth/bootstrap \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"a-long-enough-password"}'

# 2) 取出 CSRF Cookie
CSRF=$(grep qd_csrf jar.txt | awk '{print $7}')

# 3) 导入一份旧 QD 的 HAR 模板
curl -b jar.txt -X POST http://localhost:5000/api/v1/templates/import-qd-har \
  -H "x-csrf-token: $CSRF" -H "Content-Type: application/json" \
  -d '{"name":"每日签到","har":{/* 抓包得到的 HAR */}}'

# 4) 建任务，绑定模板并配 cron
curl -b jar.txt -X POST http://localhost:5000/api/v1/tasks \
  -H "x-csrf-token: $CSRF" -H "Content-Type: application/json" \
  -d '{"name":"签到","cron":"0 9 * * *","template_id":1,"timezone":"Asia/Shanghai"}'

# 5) 立刻跑一次（202 表示已入队，不等待执行）
curl -b jar.txt -X POST http://localhost:5000/api/v1/tasks/1/run \
  -H "x-csrf-token: $CSRF"

# 6) 查运行结果
curl -b jar.txt http://localhost:5000/api/v1/tasks/1/runs

# 7) 看某个 run 的每一步
curl -b jar.txt http://localhost:5000/api/v1/runs/7/steps
注意 202 与 200 的区别

触发运行返回 202 Accepted 只表示已入队。要确认执行结果，得再去查 /api/v1/tasks/{id}/runs 或订阅 /steps/live——这是异步执行框架的典型约定，别把 202 当成执行成功。

与 OpenAPI 文档的差异

本页以 crates/qdrust-server/src/api.rs 的路由注册为准。比对内嵌文档后发现 4 处遗漏：

  • DELETE /api/v1/admin/users/{id} —— 源码已注册（handler admin_delete_user），但 OpenAPI 文档未收录。本页已补上。
  • GET /api/v1/auth/config —— 源码已注册（handler auth_config），但 OpenAPI 文档未收录。本页已补上。
  • GET /api/v1/auth/oidc/callback —— 源码已注册（handler oidc_login_callback），但 OpenAPI 文档未收录。本页已补上。
  • GET /api/v1/auth/oidc/start —— 源码已注册（handler oidc_login_start），但 OpenAPI 文档未收录。本页已补上。

若你用文档生成客户端 SDK，这些端点需要手动补。
