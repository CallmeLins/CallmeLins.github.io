qdrust

用 Rust + Vue 3 重写的 QD 兼容 HTTP 定时任务自动执行框架，基于 HAR 编辑器与 Axum 服务。

v0.1.4 Rust 2024 · 1.85+ MIT linux / amd64 / arm64

它是什么

qdrust 按 QD（HTTP 请求定时任务自动执行框架）的路线重新设计，是一份独立的 Rust 实现：解析并执行旧 QD 的 HAR 模板，提供命令行工具、REST API、定时调度与 WebUI。

一句话概括它的工作：把浏览器里抓到的 HTTP 请求（HAR）存成模板，按 cron 或固定间隔自动重放执行。典型用途是签到、监控、API 轮询这类需要周期性触发的 HTTP 任务；执行结果可通过 10 种渠道推送通知。

解决什么问题

如果你曾经为了「每天自动签到」而写过脚本，大概率遇到过这些事：

  • 抓包、抠 Cookie、处理签名参数，一次性的活儿却要写成长期维护的脚本；
  • 脚本散落在各处，没有统一的调度、日志和失败告警；
  • 站点改版后签名逻辑变了，纯 HTTP 请求跑不通，又不想为一个步骤引入整套爬虫框架。

qdrust 的做法是把「请求」本身当成资产来管理：HAR 是标准格式，浏览器抓完直接导入；模板可变、可分组、可复用；调度、运行日志、步骤级回放和通知由服务端统一负责。而那些纯 HTTP 做不了的一步（JS 生成签名、验证码、多步表单），交给可选的 api://browser/* 无头浏览器插件补齐，其余步骤仍走普通 HTTP——这是刻意保持的最小设计。

核心特性

  • 旧 QD HAR 兼容：导入、校验、保留原始 HAR JSON，并重放执行。兼容样本位于 tests/fixtures。
  • 可视化 HAR 编辑器：在 WebUI 里直接编辑请求、变量与断言，无需手写 JSON。
  • 双后端数据库：SQLite（开箱即用）与 MySQL（按 DATABASE_URL 自动选择）。
  • 完整通知体系：Webhook + Email + 8 种推送渠道，共 10 种。
  • 模板表达式：minijinja 驱动的 Jinja2 语法，37 个全局函数与 51 个过滤器，外加 api://util/* 内置工具（时间 / 编码 / 哈希 / 正则 / JSON / RSA / OCR）。
  • 无头浏览器插件（可选）：api://browser/* 通过 CDP 驱动远程无头浏览器，支持跨步骤存活的会话复用与 type / click DOM 操作。
  • 任务调度：分组、批量操作、可视化调度器（含随机延迟）、模板变量预填。
  • 运行可观测：QD 风格运行日志、按任务查看运行历史、WebSocket 实时步骤流。
  • 安全与多租户：开放注册 / 忘记密码 / 邮箱验证 / CSRF 轮换；所有用户资源均做服务端归属校验。
  • 运维友好：Docker 镜像（amd64 / arm64）、管理员备份恢复、运行时配置热更新、可选 Redis 会话缓存。

与 QD 的关系

qdrust 是独立、干净重写的 Rust 实现：不继承 QD 的代码、不导入其数据库、不复用其 Cookie，仅对齐核心 HAR 兼容契约与 api://util 工具语义。

兼容范围

  • 兼容：旧 QD 的 HAR 模板（这是核心兼容契约）、api://util/* 工具语义、Jinja2 表达式写法。
  • 不兼容：旧 QD 数据库、旧登录 Cookie、旧 URL / 旧 API、任意 Python 动态表达式。

两处刻意差异

  • 单进程异步模型：采用 axum::serve + Tokio，而非 Tornado 多进程；横向扩展靠 Docker 副本 + 反向代理。
  • 非持久化本地队列：基于 SQLite 事务（claim_run + 租约恢复），保证单实例正确性与多实例不重复执行。

项目组成

仓库是一个 Cargo workspace，加上一个独立的前端工程：

组件说明
crates/qdrust-core旧 QD HAR 解析、编译、变量求值与 HTTP 执行核心。
crates/qdrust-cli无需启动服务即可校验和执行 HAR。
crates/qdrust-server基于 Axum、SQLx 与 SQLite/MySQL 的 API、认证、调度与运行管理。
crates/qdrust-plugin-browser基于 chromiumoxide 的无头浏览器插件实现。
webui基于 Vue 3、TypeScript 与 Vite 的 Web 界面。

服务端已覆盖：用户认证与会话（开放注册、忘记/重置密码、邮箱验证、CSRF 轮换）、管理员 API（用户管理、站点设置、日志清理、备份/恢复）、模板（搜索/分组/分页、可视化 HAR 编辑器、公共发布审批 PushRequest、订阅仓库自动导入）、任务（分组/批量操作、可视化调度器含随机延迟、模板变量预填）、运行记录与步骤、WebSocket 实时步骤流、租约恢复、插件系统、10 种通知渠道、可选 Redis 会话缓存、GA 注入、运行时配置热更新以及 OpenAPI。

30 秒跑起来

镜像已发布到 GitHub 容器注册表，直接拉取运行即可，无需本地构建：

# 最简启动：数据保存在命名卷 qdrust-data，监听 8923 端口
docker run -d --name qdrust -p 8923:8923 \
  -v qdrust-data:/data \
  ghcr.io/callmelins/qdrust:latest

然后访问 http://localhost:8923/，首次打开会引导创建初始管理员账号；之后其他用户走开放注册流程。运行数据默认写入 data/qd.db。

HTTPS 部署请注意

走 HTTPS 反向代理后，必须把 COOKIE_SECURE 设为 true，否则安全 Cookie 不会被浏览器接受，表现为登录会话不生效 / 反复被登出。
