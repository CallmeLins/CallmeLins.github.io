部署与运维

Docker 快速启动、生产 Compose 配置、环境变量全表、数据库选型、通知渠道，以及备份与升级回滚。

环境要求

  • Rust 1.85+（项目使用 Rust 2024 edition）——仅从源码构建时需要。
  • Node.js 24 + npm——仅本地构建 WebUI 时需要；Docker 镜像已内置前端产物。
  • Docker——推荐用于生产部署。

Docker 快速启动

镜像已发布到 GitHub 容器注册表（GHCR），直接拉取运行，无需本地构建：

docker pull ghcr.io/callmelins/qdrust:latest

# 最简启动：数据保存在命名卷 qdrust-data，监听 8923
docker run -d --name qdrust -p 8923:8923 \
  -v qdrust-data:/data \
  ghcr.io/callmelins/qdrust:latest

服务默认监听 http://localhost:8923。首次打开 WebUI 会引导创建初始管理员账号；之后其他用户走开放注册流程。运行数据默认写入 data/qd.db。

生产 Compose 配置

# docker-compose.yml
services:
  qdrust:
    image: ghcr.io/callmelins/qdrust:latest
    container_name: qdrust
    ports:
      - "8923:8923"
    volumes:
      - qdrust-data:/data
    environment:
      DATABASE_URL: sqlite:///data/qdrust.db
      COOKIE_SECURE: "true"        # 走 HTTPS 反向代理后必须开启
      QDRUST_BASE_URL: "https://your.domain"
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "curl", "--fail", "--silent", "http://127.0.0.1:8923/ready"]
      interval: 30s
      timeout: 5s
      retries: 3

volumes:
  qdrust-data:
docker compose up -d
docker compose logs -f qdrust   # 查看日志
docker compose down             # 停止

从源码构建（贡献代码时自测）：仓库自带 compose.yaml，执行 docker compose up --build -d 会构建本地 qdrust:local 镜像。

环境变量

复制 .env.example 为 .env 后按需修改。关键变量：

DATABASE_URLsqlite://data/qd.db数据库；MySQL 用 mysql://user:pass@host:3306/qdrust
DATABASE_MIN_CONNECTIONS
DATABASE_MAX_CONNECTIONS		1 / 8连接池上下限
SCHEDULER_INTERVAL_SECONDS15调度器轮询间隔，影响任务触发精度
REQUEST_TIMEOUT_SECONDS30单步 HTTP 请求超时
SESSION_TTL_SECONDS604800会话有效期（7 天）

LOGIN_RATE_LIMIT_ATTEMPTS
LOGIN_RATE_LIMIT_WINDOW_SECONDS		5 / 60登录限流
LOG_RETENTION_DAYS0已完成运行记录保留天数（0 = 永久）
QDRUST_SMTP_*空邮件发送（重置密码 / 邮箱验证 / Email 渠道）：_HOST _PORT _USERNAME _PASSWORD _FROM
QDRUST_BASE_URLhttp://localhost:8923密码重置 / 邮箱验证邮件中的链接基址

GA_KEY空注入 WebUI 的 Google Analytics 密钥
REDIS_URL空可选 Redis 会话缓存

QDRUST_CONFIG_FILE 支持在运行期热更新的键：bind、port、database_url、scheduler_interval_seconds、request_timeout_seconds、log_retention_days、ga_key、require_email_verification。其余变量仍需重启生效。

数据库

  • SQLite：默认，零配置，文件位于 DATABASE_URL 指向的路径。适合绝大多数单机与小规模部署。
  • MySQL：设置 DATABASE_URL=mysql://... 即自动切换；迁移脚本位于 migrations-mysql/。
  • 迁移是前向 only（forward-only）：升级前务必备份数据库——不存在「降级迁移」，回滚只能靠备份还原。

通知渠道

任务成功或失败时可推送提醒。系统共支持 10 种渠道，在「通知」页新建渠道并绑定到任务即可。

渠道所需配置说明
Webhookurl向该 URL POST JSON（含 event / task_name / run_id / http_status / error）
Emailto经 SMTP 发送，需先配置 QDRUST_SMTP_*
BarkurliOS 推送，形如 https://api.day.app/你的Key
Server 酱sendkey微信推送 SendKey
Telegramtoken, chat_id, host(可选)机器人；host 可指定自建 API 域名
钉钉机器人access_token自定义机器人 access_token
WxPusherapp_token, uid应用 token 与目标 UID
WxPusher SPTspt主题推送码（逗号分隔可多个）
企业微信应用corpid, secret, agentid, to_user, proxy(可选)自建应用消息；to_user 默认 @all
企业微信群机器人key群机器人 webhook key

通知标题与正文由调度器统一渲染，在 Email 与推送渠道间共享；单个渠道投递失败只记录日志，不会中断任务执行。

备份、升级与回滚

qdrust 使用不可变语义版本镜像标签。升级步骤：

  1. 停止写入并备份数据库（迁移前向 only，回滚必须连同数据库一起恢复）： 
    pwsh -File scripts/backup-db.ps1 -Database data/qdrust.db \
  -Output backups/qdrust-$(Get-Date -Format yyyyMMdd-HHmmss).db
  2. 记录当前镜像 digest，拉取目标版本并以相同的数据卷启动： 
    docker compose pull && docker compose up -d
# 或锁定到具体版本：docker pull ghcr.io/callmelins/qdrust:v0.1.0
  3. 验证 /health、/ready、登录与至少一个只读流程。
健康检查失败怎么办

停新容器 → 恢复升级前的数据库备份 → 启动记录的上一镜像 digest。仅回退镜像而不恢复数据库不被支持。详见仓库内的 docs/phase8/OPERATIONS.md 与 docs/phase8/RELEASE_CHECKLIST.md。

本地开发运行

安装前端依赖并构建 WebUI：

npm --prefix webui ci --cache .npm-cache
npm --prefix webui run generate:api
npm --prefix webui run build

准备配置并启动服务：

Copy-Item .env.example .env
cargo run -p qdrust-server

前后端分开开发时，同时起两个进程：

cargo run -p qdrust-server      # API，:8923
npm --prefix webui run dev      # Vite，:5173，API 请求代理到 Rust 服务

验证清单

cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace --all-targets
npm --prefix webui run lint
npm --prefix webui run test
npm --prefix webui run build
