推送与通知

任务成功或失败时把结果推出去：11 种渠道、批量绑定、失败阈值、自定义标题与正文模板。

渠道一览

在「通知」页新建渠道，再绑定到任务即可。系统共支持 11 种渠道，服务端自投递 3 种（通用 Webhook、自定义 HTTP、Email），其余 8 种为推送渠道。

渠道kind所需配置说明

自定义 HTTPcustom_httpurl, method(默认 POST), headers(JSON, 可选), body(可选模板)完全自定义的请求，可指向自建的 ntfy / Gotify 等；http 与 https 均可，便于内网服务
Emailemailto经 SMTP 发送，需先配置 QDRUST_SMTP_*
BarkbarkurliOS 推送，形如 https://api.day.app/你的Key

通知标题与正文由调度器统一渲染，在 Email、自定义 HTTP 与推送渠道之间共享。 单个渠道投递失败只记录日志，不会中断任务执行。

kind 列即 POST /api/v1/notification-channels 请求体里的取值，服务端会校验； 写错的 kind 会直接被拒绝，详见API 接口 · 通知渠道与绑定。

通知动作（绑定到任务）

「通知动作」描述「哪个渠道、在什么时机、推给哪个任务」。除了最基础的成功 / 失败 / 总是触发，还支持：

  • 批量绑定：一次为多个任务创建同一个动作，不必逐个任务重复配置，走 POST /api/v1/notification-actions/batch。
  • 失败次数阈值：连续失败达到阈值后才通知（统计「上次成功之后」的失败次数），过滤偶发网络抖动。
  • 仅自动执行时通知：手动点「立即运行」不触发，只对定时 / 随机延迟 / 重试触发的运行生效。
  • 自定义标题与正文模板：见下节变量。

标题与正文模板

标题与正文模板可用的变量：

变量含义
{event}触发事件（成功 / 失败 / 总是）
{task_id} / {task}任务 ID 与任务名
{run_id}本次运行 ID
{status}运行状态
{error}错误信息（成功时为空）
{log}QD 模板的运行日志
{t}运行完成时间，按任务时区渲染（未设置时区时用 UTC）
未识别的占位符原样保留

写错的 {...} 不会被替换成空值或报错，而是原样输出——所以看到通知里带着一个字面量 {taask}，就是拼错了变量名。

运维要点

  • Email 渠道依赖 SMTP：未配置 QDRUST_SMTP_* 时该渠道不可用，其余渠道不受影响。
  • Webhook 强制 HTTPS：内网明文投递请改用「自定义 HTTP」渠道。
  • 投递失败不影响任务：渠道异常只记日志，运行结果本身照常记录。
  • 删除渠道会解除绑定：DELETE /api/v1/notification-channels/{id} 会同时清理引用它的通知动作。
